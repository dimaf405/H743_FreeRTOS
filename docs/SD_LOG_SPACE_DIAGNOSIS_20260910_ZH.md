两份日志均记录 `SDLOG_MODE=2`、`SDLOG_PROFILE=1`、`SDLOG_DIRS_MAX=50`。SESS003 早期有 dropout，SESS004 没有 dropout；文件尾部的 Commander/输出状态仍更新，未解锁，`failure_detector_status=0`。这些数据不能覆盖未同步尾部，也不能证明复位前最后一刻的状态。

## 源码修正

对照 PX4 v1.17.0 commit `d6f12ad1c4f70ad3230afd7d86e971421e02fef4` 的 `src/modules/logger/util.cpp::check_free_space()`：

1. 分离回收目标与停止记录门限。PX4 回收目标为 `min(容量×10%, 300 MiB)`，停止线为 50 MiB；本地小卷将回收目标至少抬到停止线，确保先回收再停写。取消原先 `clamp(容量×5%, 64 MiB, 512 MiB)` 同时作为停写线的行为。
2. 按下一块新增 FAT 簇预测分配，触线前重新校正空闲计数并回收最旧已关闭会话。回收返回 `-EAGAIN`，本块没有写入，consumer 保留 Ring 重试；无可删候选时允许使用回收目标与 50 MiB 停止线之间的空间。
3. 日志 reader 在请求区间完成后保留 5 s 空闲补传窗口，再由 storage worker 关闭。正常完成不再依赖 QGC 必须发送 END，避免历史日志长期被保护而无法回收。
4. 空间告警同时报告实际 free/total MiB，保留目录名额不足也可能返回 ENOSPC 的事实。

这些修改不修复原卡已有 FAT 损坏，也不改变 IWDG 或健康判断。编译/静态验证与换卡或修复卡后的板端复验分别报告。
