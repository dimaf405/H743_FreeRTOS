# ADR-0002：优先复用上游模块并采用 Dima 目录命名

- 状态：Accepted
- 日期：2026-07-29
- 决策者：Dima Rover 项目

## 背景

本项目的目标不是从零重新实现差速车飞控，而是以成熟飞控项目的逻辑、功能和架构为基础，适配到 STM32H743 + FreeRTOS。此前“只参考算法、保持自有 ABI 和目录”的假设会促使项目重复设计 Parameter、SBUS、RC、Arming、Estimator 和执行器基础设施，不利于成熟逻辑复用和后续升级。

同时，产品希望目录、构建目标和自有模块体现 Dima 品牌，不希望新建名称中包含 `px4` 的产品目录。

## 决策

主要直接代码来源采用 PX4 v1.17.0；ArduPilot Rover 用于补充 Arming、Failsafe、轮速、导航和 PivotTurn 行为参考。

实施遵循：

- 已有成熟模块时，优先保留其 API、类型、数据契约、参数名、算法顺序和状态语义。
- 只重写与 NuttX、POSIX、AP_HAL、具体板卡或文件系统相关的平台适配层。
- 确实无法移植时，新增 Dima 替代实现并记录无法复用的原因。
- 产品目录、构建目标和自有 namespace 使用 Dima。
- 项目内不新建名称包含大小写不敏感 `px4` 的目录。
- 上游源码中的 `px4::`、`PX4_*`、`AP_*`、参数名、Topic 名、版权头和许可证文字保持原样，不做品牌式全文替换。
- 上游来源和本地映射统一记录在 `DIMA_SOURCE_MANIFEST.md`。

当前本地 PX4 预研快照仅为 `release/1.16`、commit `75f9a32a12`，不能冒充正式 v1.17.0。ArduPilot 行为参考 commit 为 `3f2e4763accb`。

## 备选方案

### 完全采用上游原目录名称

最便于源码对比，但不符合产品目录希望使用 Dima 命名的要求，因此不采用。

### 全文替换上游品牌、namespace 和宏

表面上目录和源码风格统一，但会破坏来源可追踪性、许可证信息和后续升级差异，禁止采用。

### 只借鉴行为并全部重新实现

可以避免直接代码依赖，但会重复制造参数、协议、安全和控制模块，成熟度与工期不可接受，因此不作为默认策略。

## 影响

### 正面影响

- 提高成熟代码和数据契约的复用率。
- 减少 Parameter、SBUS、RC、Arming、控制和 Estimator 的重复设计。
- Dima 产品边界和上游来源边界同时清晰。
- 后续可以按 Source Manifest 对比和升级上游版本。

### 代价与风险

- Dima 目录与上游原路径不完全一致，需要持续维护映射清单。
- 许可证问题不能通过改名规避，必须单独完成发布审查。
- 上游模块可能依赖当前尚未实现的平台能力，需要分阶段适配。

## 实施约束

- 许可证状态暂为 `PENDING`。
- 所有导入文件必须保留原始版权和许可证头。
- 许可证审查完成前，不得默认发布包含许可证未决代码的闭源二进制。
- 阶段 0 只建立文档、决策和资源基线，不导入 EKF2、SBUS 或控制模块生产源码。
- 当前迁移期控制代码不删除，达到新链路里程碑后再替换。

## 验证方式

- 检查新建产品目录名称不包含大小写不敏感 `px4`。
- 检查来源文档和源码许可证仍准确保留 PX4/ArduPilot 名称。
- 检查 Source Manifest 的版本、路径、许可证和修改记录完整。
- 不为本 ADR 新增测试或仿真代码。
